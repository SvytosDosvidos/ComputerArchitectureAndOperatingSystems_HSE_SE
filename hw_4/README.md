## Условие и сценарий

Два флота автономных кораблей сражаются на одинаковых квадратных полях. Каждый
корабль имеет собственный номер, положение, размер и число неповреждённых палуб.
В каждом раунде живой корабль по умолчанию выбирает столько целей, сколько у него осталось
палуб; альтернативное правило — один выстрел у любого живого корабля. Судья принимает все решения до расчёта повреждений. Потопленный в данном
раунде корабль успевает сделать уже сформированный залп. Повторное попадание в
уничтоженную палубу не уменьшает боеспособность. Игра заканчивается при
уничтожении флота или по лимиту раундов. При лимите выигрывает сторона с большим
числом целых палуб; равенство означает ничью.

Три самостоятельные программы написаны на C и работают через TCP:

- `naval_server` — судья и два логических командных центра. Он размещает флоты,
  управляет раундами, проверяет ответы, согласовывает цели внутри каждой стороны,
  рассчитывает попадания и рассылает события.
- `naval_ship` — отдельный процесс для **каждого** корабля. Получает своё
  состояние на начало раунда, самостоятельно выбирает цели и отвечает серверу.
  Корабли одинаковы по правам; тактика `random` либо `sequential` задаётся при
  запуске клиента.
- `naval_observer` — отдельный клиент общего вида. Сразу после подключения
  получает снимок состояния обоих флотов и полей, затем все события игры.
  Одновременно могут работать несколько наблюдателей. Их отключение и повторное
  подключение не задерживает игру. Медленный клиент удаляется, если очередь
  вывода переполнена.

Сервер использует неблокирующие сокеты и `poll`, поэтому принимает новых
наблюдателей и сообщения кораблей во время игры. TCP сообщения текстовые,
разделены `\n`. Основные сообщения: `HELLO SHIP FLEET ID`,
`HELLO OBSERVER`, `WELCOME SIZE LENGTH X Y SEED`, `TURN ROUND DECKS`,
`FIRE ROUND COUNT X Y ...`, `SNAPSHOT`, `GRID`, `TARGET`, `HIT`,
`MISS`, `SUMMARY`, `GAME_OVER`. Координаты начинаются с нуля.

## Сборка и запуск на Linux

```bash
cd hw_4
make
./naval_server 0.0.0.0 48022 --size 8 --fleet 3,2,1 --rounds 30 --delay 150 --seed 42 --log battle.log
```

В другом терминале запустите шесть клиентов (на том же компьютере либо на других
компьютерах, указав IP сервера вместо `127.0.0.1`):

```bash
for fleet in 1 2; do
  for ship in 1 2 3; do
    ./naval_ship 127.0.0.1 48022 "$fleet" "$ship" random &
  done
done
wait
```

В отдельном терминале можно в любой момент запустить несколько наблюдателей:

```bash
./naval_observer 127.0.0.1 48022
```

Для демонстрации динамического подключения откройте второй терминал
наблюдателя, закройте первый через `Ctrl+C`, затем запустите его снова.
Сервер продолжит бой. Автоматический вариант этой проверки включён в
`test_integration.py`.

Параметры сервера: `--size` (4–16), `--fleet` (список длин до 8 кораблей,
например `4,3,2,1`), `--rounds`, `--delay` (мс), `--seed`,
`--shots decks|one`, `--placement random|rows`, `--repeat` (разрешить
повторные цели), `--log FILE`. Размещение `random` — воспроизводимое случайное без
пересечений, горизонтальное либо вертикальное; `rows` размещает корабли
горизонтально по строкам для воспроизводимых сценариев. Некорректное размещение
завершает сервер с ошибкой. Выбор стратегии корабля — последний аргумент
`random` или `sequential`.

## Правила синхронизации и вывода

Сервер начинает бой после подключения всех кораблей. В начале раунда каждому
живому кораблю посылается `TURN`; уже потопленный корабль пропускается. Все
ответы `FIRE` проверяются по номеру раунда, выбранному правилу числа выстрелов и границам
поля. Командный центр каждой стороны до применения урона перенаправляет
повторную цель на первую ещё не обстрелянную клетку, если такая существует.
Это правило одинаково для обеих сторон. Когда свободных целей нет, повторы
неизбежны. С `--repeat` перенаправление отключено.

После получения **всех** залпов судья последовательно записывает результат
каждого выстрела; фактически состояние обоих флотов обновляется в одной фазе,
поэтому уже сформированные залпы не отменяются. `HIT` содержит координаты,
номер корабля и оставшиеся палубы; `SUNK` — гибель корабля; `SUMMARY` —
боеспособность флотов. В `GRID` буквы `S`, `X`, `o`, `.` означают целую палубу,
уничтоженную палубу, промах и неизвестную воду соответственно. Наблюдатель
получает эти сведения при подключении и далее видит `READY`, `TARGET`,
`RETARGET`, `ROUND`, `HIT`/`MISS`, `SUNK`, `SUMMARY`, `GAME_OVER`.

Обычное завершение — уничтожение флота либо лимит раундов. `Ctrl+C` сервера
завершает игру с причиной `interrupted`. Если корабль отключается посреди боя,
игра завершается с `ship_disconnected`; для требования на 8 баллов обязательна
динамическая переподключаемость именно наблюдателей. Сообщение `GAME_OVER`
отправляется кораблям и наблюдателям перед закрытием соединений.

## Проверка и результаты

```bash
make
python3 test_integration.py
```

Проверено в Ubuntu 24.04 через WSL: сборка `-std=c17 -Wall -Wextra
-Wpedantic` без предупреждений; тест с пятью раундами, отключением первого
наблюдателя и подключением двух новых; тест завершения по лимиту одного
раунда; тест альтернативных правил `--placement rows --shots one --repeat`.
Все три прошли. Тест проверяет получение снимка каждым наблюдателем,
наличие залпов обеих сторон перед фазой применения, отсутствие повторного
уничтожения клетки и корректное уменьшение числа палуб. Тестовый журнал
создаётся во временном каталоге и удаляется после проверки. Для удаления
скомпилированных файлов выполните `make clean`.

Пример события из запуска с `--seed 42 --rounds 1`: `ROUND 1 APPLY shots=6,6`,
затем `SUMMARY round=1 health=6,6` и
`GAME_OVER reason=round_limit winner=0 health=6,6`. Результат — ничья,
поскольку ни одна палуба за первый раунд не поражена.
